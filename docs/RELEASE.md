# الفصل بين التطوير ومنصة دينا

| الفرع | الغرض | يصل للمدرسة؟ |
|---|---|---|
| `dev` | ورشة التطوير: كل ميزة جديدة تُبنى وتُختبر هنا أولاً | لا |
| `main` | منصة مدارس دينا الحية (GitHub Pages حالياً) | نعم |

## القاعدة
- كل عمل جديد يُودَع في `dev` فقط.
- لا يُنقل شيء إلى `main` إلا بأمر صريح من المالك («انقل الميزة … لدينا»)، ويمكن نقل ميزة واحدة دون غيرها (`git cherry-pick` لإيداعاتها).
- كل ميزة في إيداع مستقل أو أكثر يبدأ عنوانه باسمها، ليسهل نقلها وحدها أو التراجع عنها (`git revert`).
- بعد النقل تبقى الميزة مخفية عن المعلمين حتى يفعّلها المالك من «تخصيص صفحة المعلم».
- تعديلات قاعدة البيانات (`sql/`) إضافية فقط (`create or replace`، أعمدة/جداول جديدة) فلا تكسر الفرع الآخر.

## الأوامر
```bash
# العمل اليومي
git checkout dev && git pull origin dev
# … تعديل + python3 build/build.py + الاختبارات …
git commit -am "اللجان: …" && git push origin dev

# نقل ميزات محددة إلى منصة دينا (بأمر المالك فقط)
git checkout main && git pull origin main
git cherry-pick <إيداعات الميزة>
python3 build/build.py && git commit -am "بناء" ; git push origin main
git checkout dev && git merge main   # ليبقى dev متضمناً كل ما في main

# نقل كل ما في dev
git checkout main && git merge dev && git push origin main
```

### التعديل على المنصة الأم (مسموح في أي محادثة)
1. عدّل في `src/` ← `python3 build/build.py` ← اختبر (`t70`، `t173`، واختبار الميزة) ← `git push almenasa HEAD:dev` (و`origin HEAD:dev`).
2. تعديل القاعدة للمنصة الأم: `apply_migration` عبر موصل **Almenasa** فقط، واحفظه في `sql/NNN_*.sql` وفي رأسه سطر النطاق (انظر أدناه).
3. يظهر التعديل على رابط المنصة الأم خلال دقيقة تقريباً. دينا لا تتأثر بشيء.

### نقل تعديل إلى منصة تابعة (دينا) — بأمر صريح من المالك فقط
قائمة التحقق قبل النقل:
1. **الواجهة:** الميزة الجديدة مخفية بـ `A.tfeat('مفتاح')` حتى يفعّلها المالك من «تخصيص صفحة المعلم»؛ ولا يتغير سلوك قائم إلا إصلاحاً مطلوباً.
2. **القاعدة — الترحيلات «العامة» فقط تُطبَّق على دينا:** إضافية فقط (`create or replace`، أعمدة جديدة تقبل الفراغ أو بقيمة افتراضية، جداول جديدة بـ RLS و`school_id`)، **بلا حذف ولا تعديل بيانات**. تُجرَّب على دينا داخل `do $$ … raise exception $$` (تراجع تلقائي) قبل التطبيق.
3. **ترحيلات «المنصة الأم فقط» لا تُطبَّق على دينا أبداً**، والكود المعتمد عليها يجب أن يعمل بدونها: يختفي لغير مدير المنصة (`A.isPlatformAdmin()` = false في دينا) أو يتوقف بصمت إن لم توجد الدالة (مثل `log_error`).
4. **الترتيب:** القاعدة أولاً (إن لزم) ثم الواجهة، حتى لا تطلب الواجهة دالة غير موجودة.
5. النقل: `git checkout main && git cherry-pick <إيداعات الميزة>` ← بناء ← اختبارات ← `git push almenasa main && git push origin main` ← `git checkout dev && git merge main`.
6. بعد النقل: تحقّق أن `config.js` يبقى على `dina` افتراضياً، وأن لا شيء تغيّر لمستخدمي دينا سوى المطلوب.
