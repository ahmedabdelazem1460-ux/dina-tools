# الفصل بين التطوير ومنصة دينا

| الفرع | الغرض | يصل للمدرسة؟ |
|---|---|---|
| `dev` | ورشة التطوير: كل ميزة جديدة تُبنى وتُختبر هنا أولاً | لا |
| `main` | منصة مدارس دينا الحية (GitHub Pages حالياً) | نعم |

## القاعدة
- كل عمل جديد يُودَع في `dev` فقط.
- لا يُنقل شيء إلى `main` إلا بأمر صريح من المالك («انقل الميزة … لدينا»)، ويمكن نقل ميزة واحدة دون غيرها (`git cherry-pick` لإيداعاتها).
- كل ميزة في إيداع مستقل أو أكثر يبدأ عنوانه باسمها، ليسهل نقلها وحدها أو التراجع عنها (`git revert`).
- بعد النقل تبقى الميزة مخفية عن المعلمين حتى يفعّلها المالك من «تخصيص صفحة المعلم».
- تعديلات قاعدة البيانات (`sql/`) إضافية فقط (`create or replace`، أعمدة/جداول جديدة) فلا تكسر الفرع الآخر.

## الأوامر
```bash
# العمل اليومي
git checkout dev && git pull origin dev
# … تعديل + python3 build/build.py + الاختبارات …
git commit -am "اللجان: …" && git push origin dev

# نقل ميزات محددة إلى منصة دينا (بأمر المالك فقط)
git checkout main && git pull origin main
git cherry-pick <إيداعات الميزة>
python3 build/build.py && git commit -am "بناء" ; git push origin main
git checkout dev && git merge main   # ليبقى dev متضمناً كل ما في main

# نقل كل ما في dev
git checkout main && git merge dev && git push origin main
```

## لاحقاً (عند إنشاء المستودع الخاص)
- يُنقل المستودع كاملاً بفرعيه إلى المستودع الخاص، ويُربط بـ Cloudflare Pages: الفرع `main` ← رابط منصة دينا، والفرع `dev` ← رابط معاينة خاص.
- قاعدة بيانات تجريبية مستقلة للتطوير، و`config.js` يختار القاعدة حسب الرابط.
